# v2.4.1：外因收敛与写时刻守卫

按"专业程序、显式契约、外因直接报错"收敛持久化层：路径冲突只在写入时刻由创建守卫裁决，会话自身的路径账本不再从句柄名派生，检查点失败不再株连无关目标。保持 Go 标准库、单二进制、无临时文件、无固定大小上限。

## 移除的预检

- 删除 `sameSessionPath`（`Abs`、平台大小写折叠、`EvalSymlinks` 叶/父四级回退的路径代数）。`-save` 与 `-continue` 指向同一文件——无论以相同拼写、`.` 段、相对路径还是符号链接表达——不再于启动时被拦截；程序完整执行后，退出时的另存在写入时刻被 `O_EXCL` / `CREATE_NEW` + `createdNew` 守卫拒绝，持续保存的文件完好无损。
- 删除 `-save` 启动期存在性 `Lstat` 检查。存在性同样由写时刻守卫裁决，失败与预检一样立即且不重试，只是发生在有后果的写入处。
- 句柄身份判定（`owner.matches`）收敛为"词法 `Abs` + 字符串相等"的单份共享实现，删除 Unix 与 Windows 两份平台副本；不再在运行期按平台折叠大小写。别名形态判错时，结果就是操作系统的打开/写入错误，由使用者自行解读。

这些预检本就无法覆盖硬链接、bind mount、8.3 短名等形态，且在符号链接机制最多的 Windows 上从未被测试（创建符号链接需要特权而跳过）。它们提供的安全保证是冗余的：真正的守卫在写入处，原子且不可绕过。保留它们换取的只是失败时机提前；为省下这点时间而维护一套不可完备的路径拓扑判断，得不偿失。后果由做出显式选择的用户承担。

## 自家账本的修复

- Windows `-continue` 既有文件后、首个检查点落地前，`history_read` 曾必然共享冲突失败：`decodeSession` 从独占句柄名派生 `historyPath`，而独占句柄名带 `\\?\` 扩展前缀、`owner.path` 不带，复用判定永远失配，读取退化为 `os.Open` 并撞上自己持有的独占句柄。现在 `decodeSession` 显式接收路径参数，会话自身路径永不取自句柄名。
- 检查点失败（`checkpointErr`）的粘滞从"整个会话、任何路径"限定为"失败的那个文件"：同一文件保持失败关闭、不重试、不覆盖上一个有效检查点；另存新快照或把持续保存重定向到新文件时，只复制失败文件的最后已提交前缀，不再被一次瞬时失败永久阻断。

## 验证

本地验证通过：gofmt、go vet、全量测试含 race 与 shuffle。回归覆盖：同路径、`.` 段、相对路径与符号链接表达的 `-save` 冲突在退出时安全失败且持续保存文件完好；毒化的句柄名不渗漏为会话路径；检查点失败限定在其自身文件、不阻断恢复快照与重定向。发布流程继续执行多系统 CI、Debian 打包和发布产物校验；未连接真实模型服务。
