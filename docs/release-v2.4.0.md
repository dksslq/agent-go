# v2.4.0：请求协议修复与会话语义

修复记忆整理后可能出现的 API `messages` 参数错误，拆清另存、只读加载与持续保存，并提供显式历史回溯。保持 Go 标准库、单二进制，不创建临时文件。

`memory_edit` 可以释放包含原用户消息的已完成历史，留下尚在执行的助手工具调用组。此前后续请求可能因此以助手消息开头，被严格校验的后端拒绝。现在仅在请求视图加入明确标记的用户续接锚点，工具调用与结果保持配对；原始 transcript 和保存记录不插入伪造的用户历史。旧 v4 会话可直接加载。

| 操作 | 文件与后续写入 |
|---|---|
| `/save <file>` | 另存当前状态至新文件后关闭；不改变已有持续保存绑定 |
| `/load <file>` | 只读加载后关闭；停止原持续保存，`/reload` 为别名 |
| `/continue <file>` | 载入或新建，持续保存；Windows 持续独占此文件 |
| `-save <file>` | 退出时另存；可与 `-load` 或不同路径的 `-continue` 配合 |
| `-load <file>` | 只读加载，与 `-continue` 互斥 |
| `-continue <file>` | 启动时载入或新建并持续保存 |

另存拒绝覆盖已有文件。只有持续保存会在记忆整理前持久化已完成的原文；快照不会记录后续消息，也不能补回从未保存且已释放的历史。

新增 `history_read`：模型明确提交必填的绝对索引 `start`、`end`，读取所选会话档案的 `[start, end)` 原始消息；`[0, 0)` 只查询边界。结果的 `next` 提供可读上界，`[1, base]` 标明不可恢复的原文缺口。工具只读所选档案，不接受任意路径，不隐含创建文件或缓存整段历史；Windows 持续保存时复用已有句柄。读取结果进入当前工具上下文，可再次整理。未保存的原文无法恢复。

动态的 `history_next` 与 `last_request_bytes` 只放在每轮最后一个工具结果中，避免改写旧上下文和系统前缀、浪费后端缓存。

兼容 v4 增量日志、旧 v3 对象与消息数组。检查点仍采用校验、换行提交与失败回滚，不使用临时文件或替换文件；外部程序副作用不能随检查点一起回滚。

Unix 命令正常非零退出后不再重复发送进程组终止信号；超时、主动取消和持管道后代的清理保留。

本地验证通过：Go 1.21 与当前 SDK 的测试和 vet、全量 race/shuffle、六目标交叉构建，以及真实 CLI 的执行、整理、严格请求续接、历史回溯和 API 失败退出。回归覆盖句柄释放、冲突不覆盖、失败回滚、旧会话及临时目录不可用。发布流程继续执行多系统 CI、Debian 打包和发布产物校验；未连接真实模型服务。
