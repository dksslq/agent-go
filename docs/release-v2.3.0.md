# v2.3.0：显式持久化，无临时文件

Agent 不再创建临时 JSONL 归档或保存快照。会话只写入用户明确指定的文件，保持标准库、单二进制和三个工具。

- 重写系统提示词，运行状态提供实际 OS/架构、默认工作目录和保存模式；明确工具退出语义、依赖顺序、记忆整理和中断副作用。
- 无保存时，`memory_edit` 释放已整理的原文；从未保存的原始记录不可恢复。未经整理的历史可能持续占用 RAM，退出会丢失新增记忆。控制台与模型系统消息说明这一状态，重要事实可以通过 `exec` 显式写入文件。
- `-save`、`-continue` 或 `/save <file>` 开启后续自动保存；`-load` 本身只读。已经保存时，先持久化已完成的历史再释放 RAM。运行中才保存，无法补回此前已释放且未保存的原文，程序会提示缺口。
- 新文件采用 v4 增量 JSON 日志。带校验的记录以换行提交；追加或刷新失败回滚到上一个提交位置，停止推理并退出。读取忽略崩溃产生的未提交尾部，不改写文件；仅在明确保存时清理该尾部。
- 继续加载旧 v3 对象和消息数组。旧快照保持原样，后续提交追加日志，不原地迁移。v4 文件不是单个 JSON 对象，已有直接解析 v3 的集成需要调整；使用 Agent 载入无需手动转换。
- `/save` 另存要求新文件，`-save` 使用已有非空文件时必须同时载入它，或使用 `-continue`；冲突立即失败。Windows 持续独占会话文件，其他读写及删除打开均失败，包含 `exec` 的直接读取。保存不再依赖文件替换或 POSIX 替换支持。

会话检查点不能撤销外部工具的副作用。恢复中断任务时仍应先核实文件、进程和服务状态。没有新增依赖、进程互斥或固定历史与输出大小上限。

验证覆盖无临时文件、无保存整理释放、自动保存、旧会话兼容、日志校验、失败回滚及崩溃尾部恢复；CI 继续执行竞态测试、Go 1.21 兼容检查、跨平台构建和 Debian 打包。
