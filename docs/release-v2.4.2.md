# v2.4.2：轮次取消与参数保真

本次仅修复自身状态传递与 JSON 编解码问题，清理确认无用的代码。保持标准库、单二进制、原有工具与会话格式；不增加参数、自动重试、资源限制或外部状态预检。

## 修复

- 交互模式的 Ctrl+C 原先只取消推理上下文，输出等待却绑定进程上下文。输出阻塞时，首次中断不能完成当前轮次和检查点。现在正文、推理与工具日志的输出等待使用轮次上下文；取消可以释放调用方，且不写入永久性输出错误。底层已开始的 OS 写入仍由原写入协程完成，不创建替代写入协程、不重放数据；下游恢复读取后可继续下一轮。
- `-extra` 改用 `json.RawMessage` 保存附加值，避免大整数及高精度小数经过 `float64` 后改变。重复 `-extra` 仍由后项覆盖同名字段，禁止覆盖核心请求字段的规则不变。

## 清理与保持

- 删除没有生产消费者的 `EventToolCallDelta` 及其逐分片 channel 同步；最终完整工具调用的校验、顺序和执行保持不变。
- 测试专用 `execCmd` 包装移至 `_test.go`。旧调用兼容参数保持不变。
- 交互终端继续默认显示推理；非交互推理日志以及详细工具参数、结果由 `-verbose` 控制。README 与实现对齐。

## 验证

新增真实 CLI 回归：原始 JSON 大整数、嵌套高精度数字与重复附加字段；首次 SIGINT 在 stdout 未排空时仍提交中断检查点，恢复读取后下一轮成功。新增输出等待测试覆盖已开始写入及等待交接时的取消；PTY 回归确认不开启 `-verbose` 仍显示交互推理。

发布前执行全量 race/shuffle 测试、gofmt、go vet、六目标交叉构建及原有多系统 CI、Debian 打包检查。测试使用模拟 API 和真实子进程，不以真实模型行为作为正确性保证。
