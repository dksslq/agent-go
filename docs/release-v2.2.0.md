# v2.2.0：分离命令输出

`exec` 的 `result` 由文本改为 JSON 对象，模型可以分别读取程序输出、诊断与退出码：

```json
{"stdout":"","stderr":"test failed\n","exit_code":1}
```

- `stdout`、`stderr` 始终为字符串；正常退出返回整数 `exit_code`，信号终止通常为 `-1`，未启动或后台启动为 `null`。
- 正常非零退出只通过退出码报告；超时、取消、信号终止、启动及输出 I/O 错误使用 `error`，已捕获的输出仍保留。后台启动返回 `pid`。
- `max_output_chars` 分别限制两个流的可选预览，截断通过 `stdout_truncated` / `stderr_truncated` 标记，不再把状态或截断说明混入程序输出。省略或 `0` 默认完整回传；有 `output_file` 时默认不附带预览。
- `output_file` 独占新建，完整原始字节仍合并写入一个文件，返回路径与字节数。两个流同步写入文件，各自排空；不保证跨流先后顺序。启动失败会删除本次新建的空文件。
- 复制错误独立记录，即使程序非零退出也不会掩盖管道读取失败；未完整取得输出时显式报错。
- 精简工具参数说明，删除不必要的结果转义提示。继续使用 Go 标准库，无第三方依赖、进程全局互斥或默认输出大小上限。

这是工具结果格式变更，读取旧字符串结果的集成需改为读取对象字段。v3 会话格式不变，已有会话可以继续载入。

验证覆盖独立 stdout / stderr、非零退出、超时、取消、后台启动、Unicode 预览及文件输出；CI 执行竞态测试、Go 1.21 兼容检查、跨平台构建和 Debian 打包。
